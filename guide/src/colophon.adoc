= Preface

This short, non-normative guide is intended for hardware designers, security
researchers, and operating-system and hypervisor architects who assess covert
channels in RISC-V systems. It explains how to state a timing-isolation claim,
select and evaluate mitigations, and reason about the proposed timing-fence
instructions.

Familiarity with current RISC-V specifications is assumed.
In this guide, a *security domain* is an entity or group of entities that a
security policy treats as a distinct unit of trust and protection. It may
correspond to a process, virtual machine, operating system, tenant, or trusted
execution environment. It is not defined merely by an ASID, VMID, SDID, or
privilege level.

*Timing isolation* means that, within the stated threat and observation model,
no effect of activity on one side of a specified policy boundary can be observed
through timing on the other side. The glossary in <<covert-side-channels>>
defines the remaining terms used in this guide.

This guide is non-normative.
