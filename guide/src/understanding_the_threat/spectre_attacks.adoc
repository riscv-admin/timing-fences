[[spectre-attacks]]
==== Spectre Attacks

Spectre is a family of attacks that causes victim-context instructions to run
transiently along a path that correct execution would not take, then uses their
observable microarchitectural effects to reveal a value. cite:[spectre2019]
A concrete attack needs an applicable
transient-execution mechanism, a usable gadget, a reachable secret in the
victim context, a transmission path, and a receiver with the required
observation capabilities.

===== The attack explained

The following schematic is a conditional-branch Spectre gadget. It assumes an
attacker can influence `x` and invoke the code in a victim context. The secret
must be reachable in that context.
The *4096 stride makes distinct secret-byte values affect distinct cache lines.

[source,c]
.Schematic conditional-branch Spectre gadget
----
if (x < ARRAY1_SIZE) {
    y = array1[x];
    z = shared_array[y * 4096];
}
----

====== Training

The attacker repeatedly invokes the gadget with an in-bounds `x`. On a
vulnerable scenario, this can train the relevant conditional-branch predictor
to expect the condition to be true. Predictor structures and their sharing are
implementation-specific; <<example-bht>> gives a separate predictor example.

====== Transient secret access

For an out-of-bounds invocation, the schematic address arithmetic makes
`array1[x]` select a location containing the target byte. While the bounds
check is unresolved, the processor may predict the branch taken and transiently
execute the two loads. When the check resolves false, the processor discards
the transient architectural results: `y` is not an architectural value returned
to the attacker.

====== Transmission and observation

Before that rollback, the second load can make the cache state depend on `y`.
The receiver then times accesses to the appropriately spaced regions of
`shared_array`; a faster region can reveal the encoded byte. This is
*transmission* over a covert channel.
The cache mechanism is one possible channel as illustrated
in <<example-cache>>.

If the attacker controls both the transmitting execution and receiver, this
forms a covert channel. If the victim's unintended transient execution supplies
the secret-dependent signal, it is a side-channel attack. In either case, the
attack still needs matching predictor sharing, scheduling, cache sharing, and
timing assumptions.

===== Spectre variants

The original Spectre work demonstrated conditional-branch mistraining and
indirect-branch target injection. cite:[spectre2019] Other speculative
mechanisms and transmission channels may produce related attacks.
The important structure is the
combination of transient secret access, secret-dependent transmission, and
usable observation.
